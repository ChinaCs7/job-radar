# 求职雷达（job-radar）

在自己电脑上运行的求职信息聚合工具。设好关键词、城市、薪资这些条件后，它按你定的频率持续检索多个招聘平台、社区和海外站点，把结果整理到一个可以筛选的页面里。每条岗位都带原始链接和信源。

## 按方案使用

首页「求职方案」按求职者管理多个目标。例如输入销售、策划和上海、厦门，可以预览并创建四个方案。每个方案独立保存条件、候选、AI 判断、收藏、投递状态和检索记录。复制只复制条件；归档和删除停止采集，删除后可从回收区恢复。

上方「当前方案」决定岗位、条件和运行日志的范围。账号与模型密钥仍由本机共享。指挥助手可列出、创建、修改、归档、恢复方案、启动/取消检索和查看进度；它调用受限的项目工具，不执行任意系统命令。

```mermaid
flowchart LR
  A[你的需求或简历] --> B[指挥助手 / 手动创建]
  B --> C[独立搜索方案]
  C --> D[平台采集器与访问预算]
  D --> E[岗位事实：去重和更新]
  E --> F[按各方案初筛与 AI 评估]
  F --> G[各方案的岗位结果与理由]
```

同一岗位的原始内容共享，但对小红适合、对小明不适合的判断独立。先按平台岗位 ID 去重，未变化的内容不重复评估；不同方案仍需分别判断匹配度。近期相同检索结果可在 15 分钟内复用，避免重复访问。

旧数据库首次启动会先用 SQLite 备份到 `data/jobs.before-plans.db`，历史岗位归入「原有求职方案」，保留手工收藏/投递状态。旧 AI 评分不再沿用；自动检索和历史 AI 评估默认关闭，点击重新评估后才重新调用模型。不要将备份或数据目录提交到仓库。

## 采集质量与当前边界

- Boss 的关键词与城市组合持久轮转；每轮预算内检查分页是否出现新 ID，有限补全详情；没有搜完不会宣称全量覆盖。详情登录失败也会保存已取得候选，标为部分完成并暂停平台。
- 全部平台的手动/自动检索都受每日次数限制，同一平台串行，浏览器访问串行；可取消并记录错误。重启后的未完成记录标为中断。
- 超龄岗位保留过滤原因；日期未知、正文不足或公司不明不会直接评为已确认推荐。抓取时间不当作发布时间。
- 牛客当前适配的是校园招聘入口，不支持把它当社招全站搜索。社招方案会明确报范围不支持。
- **各平台尚未全部完成实站验收**。猎聘/前程无忧有各自响应解析；部分社区/媒体仍使用链接上下文采集，缺少可靠详情与日期，只能当线索。不能将已接入的信源数量理解为都具有同等可用性，也不能保证覆盖 App 的个性化结果。
- AI 请求使用已有模型配置；失败条目延迟重试，最多三次，然后等待手动重新评估。自动化测试使用模拟模型，不证明线上模型工具调用的成功率。

- **桌面应用**：设置条件、管理信源和频率、登录账号、查看运行状态、和 AI 助手对话
- **结果页**：在系统浏览器里打开，可以按天、平台、类型、地区、匹配分、状态筛选，也能导出成单个 HTML 文件，发到手机上看
- **本机优先**：账号登录态、API key、数据都只存在你的电脑上

## 去重

同平台相同岗位 ID 更新已有事实。跨平台展示按归一化公司、岗位名、城市和工作类型保守归组，避免把不同城市的同名职位合在一起；原始记录与链接保留。跨平台归组不是可靠的职位身份认证。

## AI（可选，DeepSeek）

填了 key 以后（调用时关闭思考模式，省钱也更快）：
- 新岗位自动整理成统一字段，判断是不是招聘信息，并按你的条件打 0–100 的匹配分、写理由
- 结果页可以生成「这一天的总结」
- 指挥助手通过工具查询本地岗位并管理搜索方案，比如「列出小红的方案」「为小明创建厦门兼职方案」

不填 key 也能用，只是没有上面这些功能。全网搜索用必应，不需要 key。

「AI 用量」页记录每次调用的 token 数和估算花费（按 DeepSeek 官网价格，区分高峰 / 空闲时段），按天、按用途汇总。参考：整理 10 条岗位约 ¥0.005（空闲时段），高峰翻倍。

## 开发运行

### Boss 采集验证（2026-10-24）

当前流程：校验城市 → 打开已登录搜索页 → 从 URL 或 POST 正文核对关键词、城市、页码 → 逐页保存并去重 → 按方案初筛 → 从持久化队列补详情 → AI 评估。列表中缺少 ID、响应字段缺失、页码不符或整页重复都会停止并报告，不能当作成功搜完。详情失败延后重试，普通失败三次后暂停该条；登录或验证码要求人工处理。

真实网站验证使用独立数据库、Python / 厦门、每轮两页新增扫描预算和一条详情预算，没有调用 AI：

- 第一轮成功核验两页，每页 15 条，共 30 个不同岗位。
- 发现搜索网址的 `page=3` 被网站忽略，实际仍请求第一页。修正为从真实首页逐页回放至断点，之后成功核验第 3、4 页，断点推进到第 5 页。该轮四页共 60 个不同岗位，相对验证数据库新增 32 条；平台排名会变化，不能将分页当作静态快照。
- 随即重复执行相同方案命中 15 分钟缓存，新增 0 条，未新增采集记录。
- 两次详情提取返回正文，但只有一条达到 180 字的完整度门槛；验证库没有取得明确发布时间。详情提取成功不等于信息完整，也不等于岗位当前有效。
- 回归测试 27 项通过，覆盖响应匹配、部分失败保存、断点不回退、详情退避、方案隔离和重复岗位评估保留。

覆盖记录可通过 `GET /api/boss/coverage`（请求头 `X-Plan-ID`）查看，包含页码、回放标记、岗位数量、停止原因和详情计数，不记录账号令牌。单组合最多扫描到 20 页；遇到上限回扫首页，并不代表全站覆盖。重新打开搜索页仍需回放旧页，复用有效搜索页以减少回放尚待优化。尚未与手机端逐条对照，其他平台也不能据此视为已验收。

### 脉脉、猎聘与即刻检查（2026-10-24）

- 脉脉：已登录网页实际有帖子。旧版只寻找 HTML 超链接，漏掉了点击卡片打开的帖子。现在使用专用采集器解析页面结构化数据，获取稳定帖子 ID、正文、创建时间和可打开的详情链接；按时间排序，滚动翻页后核验关键词、偏移量和排序参数。默认每关键词最多两页，并明确只采集职言线索。账号信息、搜索令牌不进入岗位记录。
- 脉脉实测：Python 招聘查询两页共 30 条帖子，发帖日期为 10 月 16–24 日；抽查一条详情链接，网站跳转到对应社区详情页并显示帖子正文。城市、公司、招聘性质仍需抽取与核验，不能把 30 条帖子等同于 30 个匹配岗位。明确以“求内推”等开头的个人求职帖及已知过期帖在 AI 前过滤。默认开关沿用既有配置。
- 猎聘：单独使用官方城市选择器的城市代码（370 个国内城市名称），不把 SEO 城市网址当作搜索筛选。逐页核对响应中的关键词、城市代码和零起始页码，逐页保存与推进断点；未知城市报错，不回退全国。本轮页数预算默认两页，单组合扫描到第 10 页后回扫首页，不代表全站覆盖。
- 猎聘实测：Python / 厦门两页返回 84 条不同候选，按厦门及近 30 天等条件初筛保留 53 条。刷新字段中同时存在多年前的日期；保守按平台提供的日期筛选，不以抓取时间替代。列表正文仍只有公司摘要，详情完整度、在招状态和后续轮次续查仍待进一步实测。
- 即刻：本机搜索入口跳转到 App 扫码登录页。本轮没有继续尝试，也未将它记成“零岗位搜索成功”。登录后还需验证帖子日期、详情和翻页。
- 回归测试共 33 项通过；以上实时验证使用独立数据库，没有调用 AI，也没有混入正式岗位库。牛客、前程无忧等其他平台尚未完成本轮验证。

需要 Python 3.11+、Node 20+、Chrome（或 Edge）。

```bash
# 后端
cd backend
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt   # macOS / Linux: .venv/bin/pip

# 界面
cd ../ui
npm install
npm run build          # 生成 ui/dist，后端直接提供这些页面

# 桌面应用
cd ../desktop
npm install
npm start              # 拉起后端，打开窗口
```

改界面时可以用热更新：先运行 `cd ui && npm run dev`，再运行 `cd desktop && npm run dev`（窗口加载 Vite 开发服务器，后端固定使用 17860 端口）。

数据目录：开发时是项目下的 `data/`；打包后是 `%APPDATA%/求职雷达/data`。

## 目录

```
backend/app/
  main.py          本地服务（FastAPI，只监听 127.0.0.1）
  scheduler.py     调度：每个信源单独计时，间隔随机浮动；被风控就暂停，不重试
  pipeline.py      一次检索的流程：采集 → 筛选 → 去重入库 → AI 整理
  collectors/      各信源的采集器
  browser.py       专用浏览器（直接用 CDP，不注入脚本）
  llm.py           DeepSeek：整理、总结、AI 助手（工具调用）
  db.py            SQLite
ui/                React + Vite；index.html 是桌面界面，report.html 是结果页
desktop/           Electron 外壳：拉起后端、托盘常驻、在系统浏览器打开链接
```

## 使用须知

- 只供个人求职使用。请遵守各平台的用户协议，不要调高频率，也不要把数据拿去转卖。
- Boss 等需要登录的平台有封号风险：默认间隔 2 小时，夜间暂停；一旦被要求验证就自动暂停，等你人工处理。
- RemoteOK 的接口条款要求注明来源并链接回原页面，结果页里每条都带了原始链接和信源。
