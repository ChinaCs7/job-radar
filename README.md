# 求职雷达 · Job Radar

把分散的招聘信息收集到本机，按自己的求职目标筛选、跟进。

本地运行的桌面工具，聚合招聘平台、公司官网、社区及远程工作站的岗位线索。为不同方向和城市建立独立方案，定期检索、查看原文、收藏和记录投递进度；可选 AI 可以整理岗位、解释匹配理由，并根据简历设计搜索方案。

**当前处于 0.1 开发阶段，以 Windows 源码运行为主要验证环境。部分信源仍在适配，不保证全站覆盖或岗位有效性；尚未提供安装包构建流程。**

[使用指南](docs/usage.md) · [信源状态](docs/sources.md) · [开发与贡献](CONTRIBUTING.md) · [隐私与安全](SECURITY.md) · [更新记录](CHANGELOG.md)

## 功能

- **独立方案**：按求职者、方向、城市管理条件；候选、匹配判断、收藏、投递状态和日志按方案隔离。
- **多信源检索**：保留信源和原始链接，支持筛选、去重、原文查看与 HTML 结果导出。
- **后台调度**：逐来源配置频率，支持排队、取消、夜间暂停、访问预算和失败记录。
- **AI 可选**：不填 key 也能管理方案、检索、按已知字段筛选和管理岗位。
- **Agent**：流式回复、工具进度、按简历生成方案预览，支持创建方案、启动检索和查看进度。
- **本机存储**：设置、SQLite 和专用浏览器登录态保存在本机。启用 AI 时相关文本会发往模型服务，详见 [数据说明](SECURITY.md)。

投递需打开原始招聘页面自行完成。

## 建议配置 DeepSeek，提高筛选质量

基础功能不强制使用 AI；但如果希望从社区帖子、社交媒体和全网搜索线索中找出值得投递的岗位，**建议配置 DeepSeek 并开启 AI 整理**。仅靠关键词很容易混入求职帖、广告、无关方向，以及不符合城市、工作类型或远程地区限制的信息。

项目已经接入 DeepSeek，不需要额外编写模型代码。到「账号与密钥」填写自己的 key、选择模型、测试并保存，再开启 AI 整理；已有数据可在「求职方案」对相应方案选择重新评估。重新评估会产生模型费用，并清除旧的 AI 判断后重新处理，请先确认方案条件。

AI 会判断是否是具体招聘、是否符合求职条件，并输出「推荐 / 可以看看 / 不合适」与理由。查看结果时优先看推荐，再逐条核验“可以看看”；尚未判断的条目不等于合格岗位。

**AI 只能基于已采集文本筛选，不能修复失效链接、补出缺失正文、证明岗位仍在招，或让尚未适配的信源变可用。** 日期、正文或公司不足时会保守标为待核验。配置方法与质量排查见 [使用指南](docs/usage.md)。

## 安装运行

### 环境

| 依赖 | 要求 |
| --- | --- |
| Git | 获取源码与更新 |
| Python | 推荐 3.11，更高版本尚未逐一验收 |
| Node.js | 22.12+，具体引擎要求以锁文件与安装提示为准 |
| 浏览器 | Chrome 或 Microsoft Edge，用于网页信源 |
| 系统 | Windows 为主要验证环境；macOS / Linux 未完成端到端验收 |

在 **Windows PowerShell** 中逐步执行，无需激活虚拟环境：

```powershell
git clone https://github.com/ChinaCs7/job-radar.git
cd job-radar

# 后端
py -3.11 -m venv backend/.venv
./backend/.venv/Scripts/python.exe -m pip install -r backend/requirements.txt

# 界面
cd ui
npm ci
npm run build

# 桌面程序
cd ../desktop
npm ci
npm start
```

桌面壳会自动启动后端，不需要另开终端。后端只监听 `127.0.0.1`，默认从 `17860` 寻找可用端口；专用浏览器调试端口默认为 `9333`。首次安装需要联网下载依赖。

以后进入 `job-radar/desktop` 执行 `npm start`。关闭窗口会留在托盘，**右键托盘 → 退出**才会结束应用。电脑休眠、关机或断网期间无法持续检索。其他系统启动路径、热更新和环境变量见 [开发说明](CONTRIBUTING.md)。

## 第一次使用

1. 在「求职方案」创建并选择方案，填写求职者、方向和城市。
2. 在「搜索条件」确认关键词、城市、工作类型、薪资下限、发布时间和排除词。
3. 在「信源与频率」选择少量适合的来源；需要登录时到「账号与密钥」打开专用浏览器手动登录。
4. 先对单个来源点「立即检索」，到「运行日志」确认结果、过滤原因和错误。
5. 在「岗位」或浏览器结果页筛选、收藏，打开原始链接核验后自行投递。
6. 需要持续收集时开启当前方案的自动检索，并保持电脑唤醒、联网和应用运行。

### 用简历设计方案

在「账号与密钥」配置并测试自己的 DeepSeek key，打开「Agent」，上传文字型 PDF、DOCX、TXT 或 Markdown 简历，例如：

> 根据这份简历，为我设计上海和厦门的全职求职方案。按方向列出关键词、经历依据和待确认项。先预览，不创建，也不启动检索。

核对预览后继续修改，或点「创建这些方案」。Agent 也支持执行明确要求的方案操作，使用前请看 [使用指南](docs/usage.md)。

## 信源与边界

代码注册了 24 类信源，每类的范围和可用性不同：

| 类别 | 例子 | 边界 |
| --- | --- | --- |
| 招聘平台 | Boss、猎聘、前程无忧、智联、牛客 | 部分已实测；分页、城市和详情支持不同 |
| 公司官网 | 腾讯、字节、小米、美团、网易、米哈游 | 有限批次，部分正文或日期不足 |
| 社区与媒体 | V2EX、电鸭、脉脉、知乎等 | 帖子可能只是线索，不等于在招岗位 |
| 全网搜索 | 必应、可选付费搜索 | 摘要需要回原文核验 |
| 海外与远程 | JobSpy、RemoteOK、Remotive、Himalayas、WWR、HN | 接口或最新列表的有限范围 |

58、小红书招聘官网等适配未完成；验证码、登录失效和网站变化也可能使来源暂时不可用。**请先看 [逐信源状态](docs/sources.md)，不要把“已接入”理解为“全部可用”。**

同平台按岗位 ID 去重，跨平台按公司、职位、城市等保守归组并保留原始记录。AI 评分只是辅助；采集时间不等于发布日期，信息不足的候选需要人工核验。

## 数据与更新

源码运行的数据位于项目根目录 `data/`，不进入 Git，包括设置、数据库、导出文件和 `chrome-profile/` 登录态。`settings.json` 可能含明文 API key。Agent 聊天在界面浏览器本地存储中，**单独备份 data 不包含完整聊天**。

更新前从托盘退出并备份 `data/`，然后在仓库根目录执行：

```powershell
git pull --ff-only origin main
./backend/.venv/Scripts/python.exe -m pip install -r backend/requirements.txt
cd ui
npm ci
npm run build
cd ../desktop
npm ci
npm start
```

旧数据库迁移前会备份为 `data/jobs.before-plans.db`，历史岗位归入「原有求职方案」。更多信息见 [备份与恢复](docs/usage.md)。

## 技术结构

```text
backend/app/       FastAPI、SQLite、调度、采集器与 Agent 工具
backend/tests/     自动化回归测试
ui/                React + TypeScript + Vite，桌面界面与结果页
desktop/           Electron 外壳、托盘与后端进程管理
docs/              使用方法、信源状态与验证记录
data/              运行数据（忽略）
work/              验证产物（忽略）
```

```mermaid
flowchart LR
    A[手动条件 / 简历] --> B[独立方案]
    B --> C[采集与访问预算]
    C --> D[岗位事实与去重]
    D --> E[按方案筛选]
    E --> F[岗位管理与原始链接]
    E --> G[可选 AI 整理与匹配]
    G --> F
```
