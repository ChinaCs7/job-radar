# 使用指南

[返回 README](../README.md)

## 方案与条件

「当前方案」决定岗位、条件和日志范围。账号与 key 本机共享，方案不是多用户安全边界。创建时可预览方向 × 城市组合，例如销售、策划与上海、厦门生成四份方案。

- 关键词贴近岗位名称。每轮可能只处理有限组合，单次运行不代表全部搜索完成。
- 城市为空表示不限，但来源的城市支持可能有限，遇到未适配城市请查看日志。
- 薪资单位为月薪 K。已知下限留约 20% 余量，例如设置 15K 时，已知下限低于 12K 的岗位会被初筛排除。薪资未知不代表满足要求。
- 全职、兼职、实习、合同 / 外包属于工作类型；远程属于地区选项。
- 发布时间未知的候选需要核验，发现时间不等于发布日期。
- 没有 AI 时，只能依据采集到的已知字段筛选。

复制只复制条件；归档和删除停止采集，删除可从回收区恢复。不同方案的匹配判断和投递状态独立，原始岗位事实可以共享。

## 登录与检索

先看 [信源状态](sources.md)，选择少量适合的来源。到「账号与密钥」打开专用浏览器手动登录，日常 Chrome 的登录态不会自动复制。遇到验证码或登录失效，先处理，再恢复暂停来源。

「立即检索」提交后台任务，排队不代表失败。浏览器来源串行运行，并受冷却、每日预算、夜间暂停与来源状态约束，不保证严格按分钟执行。

新增为零可能是去重、条件过滤、缓存复用或来源失败，不一定代表没有岗位。近期相同检索可能复用 15 分钟缓存。请分别查看新增数、过滤理由、部分完成和错误记录。

自动运行需要开启当前方案的开关，保持电脑联网和唤醒。取消采集使用采集按钮；关窗口仅隐藏到托盘，右键托盘「退出」才结束程序。

## 岗位与导出

筛选、收藏并记录投递状态，打开原链接核验日期、正文和当前在招状态，再自行投递。HTML 导出是静态快照，不会继续同步；分享前检查是否含个人匹配理由和不宜公开的内容。

## Agent 与简历

### 先启用岗位 AI 筛选

在「账号与密钥」填写自己的 DeepSeek key、选择可用模型，测试并保存，开启 AI 整理。项目已包含模型调用、事实提取与按方案匹配，不需要额外安装模型插件。模型配置本机共享，评估按方案独立进行。

已有数据可在「求职方案」找到对应方案并使用重新评估操作，先确认关键词、城市、工作类型与个人描述。该操作会开启该方案评估、清除旧判断并重新排队，产生 API 费用；大批数据应先检查是否值得重评。未触发重评的历史方案可能保留旧判断，保存 key 不等于所有历史数据自动重跑。

“推荐”代表模型判断符合条件且已知字段较完整，不保证岗位仍有效。“可以看看”包含相关但关键信息不明确的线索。“不合适”可能只是城市、方向、薪资或工作类型不匹配，并不代表原始信息是假的。

岗位列表可以分别选择 AI 结论；未判断条目不是模型认可的结果。非招聘内容和已知规则不符项会进入已过滤区，可查看原因；AI 判为不合适的条目默认隐藏。收藏和已投状态不会因为自动过滤被删除。

### 为什么仍有很多不可用线索

先区分不匹配、资料不足、非招聘与链接失效：

- 不匹配：收窄关键词、地区与来源，再确认个人描述是否过度限制。
- 资料不足：需要采集器补全详情和日期；让模型重新评分不能凭空补齐。
- 非招聘：AI 识别求职帖、讨论、广告和课程等噪声，保留过滤原因供复查。
- 来源未适配或访问失败：先查运行日志与信源状态，不是增加模型调用就能解决。

评估效果应关注可核验且与目标相关的岗位数量，不以采集总数或 AI 推荐数量作为成功标准。

### 使用简历与对话

在「账号与密钥」配置并测试自己的 DeepSeek key。费用由服务商收取，应用估算不替代账单；默认模型名和价格可能过时，请核对服务商当前配置。

附件支持文字型 PDF、DOCX、UTF-8 TXT、Markdown，最大 10 MB，最多提取 12,000 字符进入附件文字。不支持扫描件 OCR。

推荐先说：

> 根据简历，为我设计上海和厦门的全职求职方案。按方向列出关键词、经历依据和待确认项。只预览，不创建，不检索。

核对预览后继续调整，或点「创建这些方案」。预览不写入方案、不启动检索。也可要求列方案、启动当前方案检索、查看进度。

Agent 可以执行明确要求的修改、归档和启动操作，**并非每种操作都有独立确认弹窗**，执行后请核对。工具授权与跨请求防重复仍待完善。

「停止回复」不撤销已执行操作，也不取消另行启动的检索；断线后先查任务状态，避免重复提交。每轮有限制调用次数与时长；最近 20 条消息进入模型上下文。

聊天按方案保存在当前界面浏览器存储，没有服务端恢复或跨设备同步。手机号、邮箱与身份证号按规则遮蔽，不保证全面匿名化；姓名、公司和经历可能保留，详见 [隐私说明](../SECURITY.md)。

## 备份、更新与恢复

1. 从托盘退出应用，避免数据库写入时复制。
2. 备份整个 data，其中可能包含明文 key、登录态、个人描述和导出文件。
3. data 不包含界面浏览器中完整的 Agent 聊天。
4. 按 README 更新、安装依赖、重新构建并启动；仅刷新页面不会更新后端。
5. 换电脑建议重新填写 key、重新登录，不要公开传输浏览器配置。

方案迁移前保存 jobs.before-plans.db，旧 AI 评分不继续沿用。恢复旧库前保留当前数据副本，并使用兼容代码版本，不要在运行中替换数据库。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 找不到后端程序 | 按 README 在 backend/.venv 创建环境并安装 requirements |
| 界面空白或资源缺失 | 在 ui 运行 npm ci、npm run build，然后重启 |
| npm 引擎版本不支持 | 检查 node --version，对照锁文件要求 |
| Electron 下载失败 | 检查网络或可信包镜像，不要关闭证书验证 |
| 找不到浏览器 | 安装标准路径 Chrome / Edge，其他系统检查 PATH |
| 登录态没生效 | 使用应用打开的专用浏览器登录 |
| 一直排队 | 浏览器来源串行且有冷却，看日志避免反复点击 |
| 改完代码功能没变 | 重建界面，从托盘退出后重启 |
| 简历读不出来 | 使用有文字层的 PDF、DOCX 或纯文字，不支持图片 OCR |
| AI 不可用 | 检查 key、余额、模型名称；基础检索无需 key |
| 日期或详情不足 | 回原页面核验，AI 不能补出不存在的事实 |

反馈时附系统、提交号、来源与脱敏错误，不要上传 data、简历或完整浏览器配置。
